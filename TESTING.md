# Testing

The IEEE metadata repair's current results are in `docs/IEEE-METADATA-FIX.md` and `docs/evidence-v1.1.1/`. Its 13 additional frontend tests cover the observed IEEE JSON structure, Unicode, normalization, fallback priority, bounded dynamic loading, stale navigation, full native payload mapping and useful failure states. `scripts/verify-metadata.mjs` adds actual Chrome → native host → SQLite → Paper Inspector checks to the existing native-extension harness. Live source inspection and live Chrome import attempts are recorded separately. Set `YARA_SKIP_LIVE=1` only when rerunning local regressions without repeating previously unavailable live-page attempts; the previous attempt records are retained and labeled.

Run all commands from the project root. Tests use temporary directories, separate browser storage, or a dedicated `YARA_DATA_DIR`, never the researcher's normal desktop workspace.

The browser suite uses installed Microsoft Edge. Install Edge or change Playwright's channel if unavailable. It tests a separate persistent browser adapter. Mocked provider responses in this suite verify deterministic UI behavior; they are not proof of live provider availability.

Rust tests verify schema initialization and migration version rejection; DOI normalization; exact duplicate detection; conflicting identifiers; preservation of manual corrections; shared citations and repeated edges; foreign keys, self-edges, and cycles; status/hiding preservation; coordinates; savepoint rollback; Unicode Markdown; missing files; external edits; path traversal; recoverable deletion; consistent complete backup/restore; corrupt and unsafe archives; cache storage; OpenAlex parsing, citation filters, abstract reconstruction, and pagination. Local HTTP fixtures test invalid keys, rate limits/Retry-After, malformed JSON, offline connections, and timeouts without depending on a real provider.

The native smoke script launches only the project's release executable, with a unique workspace under `.tooling/native-proof/`. It enables a loopback WebView2 debug port solely for that child process and attaches Playwright to its real webview. It exercises visible UI plus real backend IPC, edits an actual note externally, verifies conflicts, restores a backup, restarts the executable, and attempts live OpenAlex queries. Version 1.1 logs go to `docs/evidence-v1.1/native-smoke.json`; original v1.0 evidence is preserved. It can launch the configured/detected VS Code to verify editor integration; the application's built-in editor remains independent.

The extension/native harness uses a separate base directory under `.tooling/extension-native-proof/` and fresh browser profiles. A hand-authored fixture at `tests/fixtures/ieee-article.html` is routed to the expected IEEE article URL **only inside those test browsers**. The real browser extension action grants activeTab; the same extension UI is opened in a background tab for stable automation. Its actual scripting API reads the active article, then its actual nativeMessaging API launches the compiled host. The host writes the desktop's real SQLite store. No permissions are added for tests. Chrome Developer mode is enabled only in its disposable profile. The harness snapshots and restores the two current-user host registry registrations in a finally block; its rollback file stays with the test data. Do not run it concurrently with another extension-host registration test.

These are genuine local browser-to-host-to-desktop checks with fixture source content, not proof of live IEEE extraction. Real IEEE verification barriers are not bypassed. Provider agreement and unknown/absence rules are also covered by deterministic frontend tests; metadata-only provenance cannot grant badges. Rust tests cover schema 1 migration, format 1 archive restoration, complete pagination, source history, identity collision rejection, workspace isolation, captures, receipts and backup preservation.

Do not run two Playwright suites with the same output directory simultaneously; they reset their own artifact directory. Avoid modifying frontend source while a suite is running because Vite HMR intentionally reloads changed components. Build, native, tooling, and evidence folders are excluded from the Vite watcher.

For manual acceptance, verify installer installation/uninstallation on a clean Windows machine, WebView2 bootstrapping on a machine without WebView2, default Markdown editor associations, and unsigned installer trust behavior. See `docs/VALIDATION-v1.1.md` for current results and `docs/VALIDATION.md` for the preserved v1.0 record; build success alone does not prove distribution acceptance.
